# ShakeDown — Approved Birthday Edition Gameplay Contract

## Current authority and scope
This document supersedes the older four-level design (Riverwalk, Eddy Street, Fox Den). The October 11, 2026 directive locks **one self-contained birthday adventure** with two substantial halves and a Fox confrontation. The shake is stolen, NOT a birthday-cake-rescue quest. Cake appears only as a post-boss celebration.

## Experience
**Intro:** a Fox steals the last Shamrock Shake from a campus stand; Cinnamon Fuzzbutt, the glasses-wearing orange/cream red panda in a blue band and olive shorts, pursues it.

**Campus adventure / 0..3770 world px:** safe beginning; responsive move/jump/double-jump; GO IRISH pulse makes blue-and-gold banner bridges solid; tail-swish activates drum beacons; optional shake collectibles, Cup Crawler robots, confetti cannons, moving supply cart, 2 checkpoints, collectible secrets. Avoid impossible gap or inaccessible collectible gating.

**Golden Dome / 3770..8350 world px:** >=50% of route length with 23 rising platform stages, moving platforms, two pulse shortcuts with always-available safety ledges, architecture and golden dome/statuary silhouettes, two ascent checkpoints, summit checkpoint and arena. Camera tracks vertical world coordinates and looks ahead horizontally.

**Fox battle / Dome summit:** 3 health; charge and confetti volleys; strong red/warm telegraph; hit only during recovery; defeated Fox triggers birthday victory. Boss currently uses provisional vector stand-in pending canonical Fox artwork.

**Victory:** player sees a cake and independent green milkshake sprites, visible confetti, and `HAPPY BIRTHDAY, MAVERICK!`; replay button resets the journey. No Bethel theme.

## Technical profile
- Static HTML/CSS + ES modules; Canvas 2D with DOM menus and controls, no runtime dependencies.
- Fixed-step update 1/60s, capped accumulated step count, simple AABB one-way platforms, deterministic scripted encounters, camera follow.
- Unified edge/held keyboard and multi-pointer touch inputs; no duplicate action dispatch. Pause/visibility/blur clear held inputs and freeze simulation.
- User-gesture Web Audio tones and quiet looping melody, mute always possible. LocalStorage settings and best shake count in a versioned record; failure does not block game.
- Real source-cutout Cinnamon sprites loaded from verified frames.json, with a visible fallback if unavailable. Other visuals explicitly render procedurally pending LM Arena delivery; no runtime references to nonexistent files.
- Accessible HTML controls with labels, touch areas >=48px; assist mode/reduced-motion options. Logical canvas 960x540, DPR capped at 2.

## Round 4 implementation addendum — persistence and accessibility (2026-10-11)

This is a compatible extension of the existing single-adventure gameplay plan. It does **not** change Notre Dame, the Golden Dome, Cinnamon's character identity, the Fox, collisions, the final birthday cake or the LM Arena asset-generation contract.

- A versioned localStorage record continues to preserve settings, earned completion and best Shake count. It now optionally contains the **last reached checkpoint** with verified authored checkpoint ID, elapsed simulation time, collected Shake IDs and defeated Cup Crawler IDs. The record is deliberately small, bounded, validated against actual level objects, and not a full game-state dump. An invalid/old checkpoint is ignored.
- The title has an optional Continue button for a valid checkpoint; Start intentionally resets the current unfinished route. Completion remains monotonic through replay/settings changes. Victory removes pending progress but retains a successful completion.
- Reduced Motion now changes decorative Canvas animation/flashing and preserves the authoritative game simulation and moving collision platforms. Respect platform preference by default without overriding a previously saved explicit player selection.
- Keyboard-only interaction now respects active buttons, ignores repeated pause/mute actions, supports keyboard-focused touch controls, restores focus to the game after overlays and contains Tab focus within active dialog overlays.
- All added behaviors require Node and real served-HTTP browser tests. Virtualized full-route regression timing is not evidence of human reaction time, device speaker output or real phone performance.
